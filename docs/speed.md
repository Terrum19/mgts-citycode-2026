# Скорость связки и что из неё следует для финала

Замер от 18.11. Документ для тех, кто не следил за экспериментами.

## Что за связка

На финале выдадут папки вида «Тип - Дефект» с фото. Нужно научиться относить новое фото к одной из папок. Связка состоит из трёх частей:

1. **Признаки + логрег.** Открытая модель DINOv2-base (без дообучения) превращает фото в вектор из 1536 чисел. На этих векторах учится логистическая регрессия. Это самый быстрый и надёжный вариант.
2. **Дообучение хвоста DINOv2.** Первые 10 блоков DINOv2 заморожены, их выход считается один раз. Учатся последние 2 блока и линейная голова, 12 эпох, вход 448×448. Этот вариант заметно лучше на кадрах, где дефект маленький, например при съёмке с машины.
3. **Qwen-VL (235B, через OpenRouter).** Модель отвечает без обучения. Её ответ добавляется к вероятностям классификатора как «второе мнение» с весом 0.3–1.

Какая комбинация лучше, зависит от данных, единого победителя нет:

| Данные | Логрег | Дообучение 448 | Лучшая комбинация |
|---|---|---|---|
| Люки, открытый набор (holdout 50/50) | 0.700 | 0.673 | все три: 0.720 |
| RDD2022, фото дорог с машины (train 500 → test 648) | 0.495 | 0.643 | дообучение + Qwen: 0.664 |

Метрика в таблице: macro-F1 на отложенной выборке.

Поэтому на финале комбинацию выбираем на месте:

1. Делим выданный train на 80/20.
2. Учим все варианты на 80%.
3. Выбираем лучшую комбинацию на 20%.
4. Переобучаем её на 100% и делаем предсказания.

Оставался вопрос, успеет ли дообучение за ~3 часа финала на наших ноутбуках. Этот замер на него отвечает.

## Результаты замера

Скрипт: [src/bench_speed.py](../src/bench_speed.py). Время указано на одно фото; эпоха — один проход дообучения по всем train-фото.

| Этап | CPU Intel Ultra 9 | MacBook Air M4 (MPS) |
|---|---|---|
| Признаки DINOv2, 224 | 185 мс | 27 мс |
| Признаки DINOv2, 448 | 510 мс | 117 мс |
| Подготовка к дообучению (448) | 446 мс | 99 мс |
| Дообучение, одна эпоха | 264 мс | 77 мс |
| Обучение логрега (500 фото) | 2.8 с | ~0 с |

Оценка на финал при 500 фото train, 650 фото test и 12 эпохах:

| | CPU Ultra 9 | M4 |
|---|---|---|
| Признаки для логрега | ~10 мин | 2.3 мин |
| Подготовка к дообучению | ~12 мин | 2.7 мин |
| Дообучение, 12 эпох | ~26 мин | 7.7 мин |
| **Всего без Qwen** | **~48 мин** | **~13 мин** |
| Полный цикл с выбором на 80/20 | ~75 мин | ~20–25 мин |
| Qwen на test (параллельно, по сети) | ~16 мин | ~16 мин |

Числа для CPU получены в быстром режиме (`--quick`). На логрег на M4 не смотрите: в замере он учится на случайных данных. На реальных признаках обучение займёт секунды, и на итог это не влияет.

## Выводы

- **Основная машина на финале — M4.** Полный цикл с выбором комбинации занимает около 25 минут, из 3 часов это меньше трети.
- **Дообучение на 448 точно включаем в план.** По времени оно нас не ограничивает.
- **Остаётся запас.** Его можно потратить на усиление дообучения:
  - учить 4 блока вместо 2;
  - вход 672 (для мелких дефектов);
  - 2–3 запуска с разными сидами с усреднением.
  
  Каждый пункт примерно удваивает время дообучения. Даже со всеми пунктами укладываемся в час.
- **Если данных больше.** Время растёт линейно с числом фото: при 2000–3000 фото выйдет около часа.
- **CPU Ultra 9 — запасной вариант.** Он втрое медленнее, но тоже успевает.

## Как повторить на своей машине

Скрипту нужен только сам файл, данные не нужны: фото он генерирует сам, на скорость их содержимое не влияет.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install torch transformers scikit-learn pillow numpy requests
python src/bench_speed.py --quick   # проверка, что всё работает (~2 мин)
python src/bench_speed.py           # сам замер (~5 мин)
python src/bench_speed.py --qwen 8  # + замер Qwen (нужен OPENROUTER_API_KEY)
```

Ноутбук должен работать от сети, тяжёлые программы лучше закрыть. Скрипт сам выбирает устройство (MPS, CUDA или CPU) и печатает его в первой строке вывода.
