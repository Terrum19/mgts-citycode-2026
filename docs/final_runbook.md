# Инструкция: обучение и запуск на финале

Все основные команды выполняются через `src/pipeline.py` из корня проекта. Пути `data/final_train` и `data/final_test` ниже — примеры: замените их на реальные пути организатора.

## Быстрый выбор

| Данные и задача | Маршрут | Что делает | Обучение |
|---|---|---|---|
| Один класс на целую фотографию | `final` | Обучает, проверяет варианты и предсказывает test | Логрег и/или хвост DINOv2 |
| Новые фото после `final` | `photo_dino` | Загружает модель и выдаёт один класс на фото | Не требуется повторно |
| Несколько объектов; тестовые рамки готовы | `boxes_dino` | Классифицирует вырезы по готовым рамкам | Классификатор кропов |
| Несколько объектов; рамки нужно найти | `det_dino` | Mask2Former ищет объекты, DINOv2 классифицирует вырезы | Классификатор кропов |
| Несколько объектов; разрешён внешний API | `qwen235` | Qwen ищет объекты и определяет состояние | Без обучения |
| Mask2Former + разрешённый API | `det_qwen235` | Mask2Former ищет рамки, Qwen анализирует вырезы | Без обучения |

`det_dino` и `boxes_dino` используют одну модель кропов. `final` и `photo_dino` работают с целым фото. Это разные чекпоинты, их нельзя подменять. Описания формирует Qwen; локальные кроп-маршруты описания не генерируют.

## 1. Начало работы

```bash
cd /путь/к/mgts-citycode-2026
source .venv/bin/activate
python src/pipeline.py --list
python src/pipeline.py --help
```

Если окружения ещё нет, подготовьте заранее, при наличии интернета:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-detector.txt
```

Нужен Python 3.11 или новее. На Windows активируйте `.venv\Scripts\activate` в cmd или `.venv\Scripts\Activate.ps1` в PowerShell.

### Веса и устройство

Для DINO нужны `weights/dinov2-base`; для Mask2Former — его веса. В текущей рабочей копии Mask2Former настроен на `weights/mask2former-mapillary` в `[detector].model`. На другой машине проверьте и веса, и путь. Офлайн-проверка загрузки:

```bash
HF_HUB_OFFLINE=1 python -c 'from transformers import AutoModel; AutoModel.from_pretrained("weights/dinov2-base"); print("DINO OK")'
HF_HUB_OFFLINE=1 python -c 'from transformers import AutoImageProcessor, Mask2FormerForUniversalSegmentation; p="weights/mask2former-mapillary"; AutoImageProcessor.from_pretrained(p); Mask2FormerForUniversalSegmentation.from_pretrained(p); print("Mask2Former OK")'
python -c 'import torch; print("CUDA:", torch.cuda.is_available(), "MPS:", torch.backends.mps.is_available())'
```

`--device cpu`, `--device mps` или `--device cuda` задаёт устройство явно. При `auto` для целых фото выбирается доступное устройство, а кропы и детектор используют настройки конфига. CUDA потребует подходящей сборки PyTorch. Проверяйте на той машине, которую берёте на финал.

`--dry-run` проверяет параметры и пути, не загружая модели и не запуская API. Эта проверка не гарантирует корректность данных, наличие зависимостей и работоспособность моделей.

### Доступ к Qwen

Если разрешено отправлять фото внешнему сервису, настройте `OPENROUTER_API_KEY` в окружении или `.env`; проверьте модель, лимиты и связь на одном разрешённом фото. API может взимать плату. `qwen235` и `det_qwen235` обращаются к нему по самому выбору маршрута. Для `final` Qwen выключен, пока не добавлен `--qwen`.

## 2. Наши панорамы: обучение и тест

Данные:

- `data/raw/panoramas/` — фото; `meta.jsonl` содержит координаты и сведения о сборе, но не рамки и не состояния объектов. Его `ok` означает успешное получение панорамы.
- `data/labels.json` — человеческая разметка, экспортированная из Label Studio; содержит рамки, типы, состояния и разделение `dev`/`test`.

Если разметку нужно обновить, подключитесь к ZeroTier команды и выполните:

```bash
python src/label/export.py
```

Для экспорта нужны `LABEL_STUDIO_URL` и `LABEL_STUDIO_TOKEN` в `.env`; для персонального токена укажите `LABEL_STUDIO_TOKEN_TYPE=pat`, для legacy — `legacy`. Экспорт перезаписывает `data/labels.json`. Не публикуйте токены.

**Обучить классификатор, если его ещё нет, и оценить на test:**

```bash
HF_HUB_OFFLINE=1 python src/pipeline.py \
  --variant det_dino \
  --train if-missing \
  --annotations data/labels.json \
  --train-images data/raw/panoramas \
  --split dev \
  --dataset pano_test
```

Чтобы обучить заново после изменения данных, замените `if-missing` на `always`. Это перезапишет текущий `weights/crop_dino.joblib`; если старую модель нужно сохранить, задайте другой путь `--checkpoint weights/crop_new.joblib` и используйте тот же путь при последующих запусках.

Результаты оценки: `runs/pano_test__det_dino/metrics.json`, `preds.json` и изображения ошибок в `review/`. При том же имени набора/варианта используется кэш предсказаний. После изменения содержимого фото с теми же именами используйте новый набор в конфиге или удалите соответствующий кэш перед запуском.

**Важное ограничение наших данных:** в ранее выгруженном `dev` было всего три повреждённых объекта, по одному на класс. Текущий классификатор отправляет недостаточно представленные классы в `review`; обучить надёжное распознавание дефектов по ним нельзя. Не переносите test в train для улучшения тестовой метрики.

## 3. Один объект / один класс на фото

### Подготовка

Разложите train по папкам классов. Название папки целиком становится меткой:

```text
data/final_train/
  Колодец - исправен/
    001.jpg
    002.jpg
  Колодец - крышка сломана/
    003.jpg
    004.jpg
data/final_test/
  test_001.jpg
  test_002.jpg
```

Также поддерживается структура `Колодец/исправен/001.jpg`. Фото в корне train пропускаются. Если есть Excel/CSV, положите его в папку соответствующего класса; колонка с именами фото определяется по совпадениям. Колонка `Группа` позволяет не разносить похожие кадры одной серии при внутреннем разбиении. Без неё группа — путь к фото, и похожие кадры могут попасть в обе части.

Проверьте количество фото и распознанные классы:

```bash
python src/folders.py data/final_train
```

Название исправного состояния должно распознаваться функцией `is_ok` в `src/classify.py`: например, `норма`, `исправен`, `без дефектов`, `ok`, `good`, `normal`. Название `целый` по умолчанию не распознаётся как исправное. Это влияет на метрики повреждений и отчёт. Нужны хотя бы два класса и достаточное число независимых групп в каждом.

### Обучение и предсказание

**Автоматически сравнить варианты на внутренней validation:**

```bash
python src/pipeline.py --variant final \
  --train-images data/final_train --images data/final_test \
  --training auto --out out/final
```

Программа обучает логистическую регрессию и хвост DINOv2, сравнивает их и среднее по macro-F1, обучает выбранную связку на всём train и делает предсказания. `final` всегда запускает обучение.

Вместо `auto` можно указать:

- `--training head` — только логистическая регрессия; DINOv2 заморожен.
- `--training tail` — обязательно обучить последние блоки DINOv2 и выбрать этот вариант.

Для хвоста доступны `--epochs 12`, `--k 2`, `--size 448`. Размер должен быть кратен 14; при нехватке памяти можно попробовать `--size 336`, затем заново проверить качество. Режим `head` всё ещё использует подготовку токенов из `final.py` и не является минимальным по памяти.

Для неразмеченного test по умолчанию используется `--test-format images`, в том числе при наличии подпапок. Если test размечен папками тех же классов, добавьте `--test-format labeled` — тогда будут рассчитаны метрики test. Добавление `--qwen` отправляет validation и test внешнему сервису и может включить ответы Qwen в выбранную связку; используйте отдельную `--out`, чтобы не переиспользовать устаревший кэш ответов.

Выходные файлы в `--out`: `predictions.xlsx`, `predictions.csv`, `report.json`, `photo_dino.joblib`; при Qwen также `qwen.json`. Оценка validation использована для выбора модели и может быть оптимистичной. На неразмеченном test истинную точность посчитать нельзя.

### Новые фото без повторного обучения

```bash
python src/pipeline.py --variant photo_dino \
  --checkpoint out/final/photo_dino.joblib \
  --images data/new_photos --out out/new_photos
```

`predict.py`, вызываемый скриптом, читает изображения непосредственно внутри папки, не рекурсивно. Результат для каждого фото — один объект без рамки. Гибридный чекпоинт с Qwen требует соответствующей настройки `qwen` в `[variants.photo_dino]`; для надёжного локального повторения обучайте без `--qwen`.

## 4. Несколько объектов на кадре: кропы

### Подготовка обучения

Нужны фотографии и JSON с рамками и состояниями объектов, например `data/train_boxes.json`:

```json
[
  {"file":"001.jpg", "objects":[
    {"bbox":[10,20,130,180], "type":"manhole", "status":"ok", "damage":null}
  ]},
  {"file":"002.jpg", "objects":[
    {"bbox":[30,40,160,190], "type":"manhole", "status":"bad", "damage":"cover_broken"}
  ]}
]
```

`file` — путь относительно папки фото, `bbox` — пиксельные `[x1,y1,x2,y2]`, `status` — `ok` или `bad`. Типы и дефекты должны совпадать между train и test. COCO/YOLO и другие форматы потребуется преобразовать: универсального конвертера разметки финала нет. Если указать `--split dev`, скрипт возьмёт только записи, где `split` равен `dev`; без поля split не указывайте этот параметр.

Скрипт сам вырезает объекты, извлекает признаки DINOv2 и учит логистическую регрессию. Веса DINOv2 и Mask2Former не дообучаются. Для каждого типа нужны представители `ok` и `bad`; текущий код требует минимум два примера класса, чтобы подтвердить результат. Это технический минимум, а не гарантия качества.

### Mask2Former ищет рамки: `det_dino`

```bash
python src/pipeline.py --variant det_dino \
  --train always --annotations data/train_boxes.json \
  --train-images data/train_images \
  --images data/test_images --out out/det
```

Для последующих запусков уберите параметры обучения и используйте `--train never` или просто опустите его. Для пробного прогона добавьте `--limit 5`. Параметр `--meta data/photos.xlsx` добавляет метаданные; также поддерживаются CSV и JSONL. Проверьте, что имена фото и строки таблицы сопоставились.

### Рамки известны: `boxes_dino`

Для test создайте `data/test_boxes.json` с записью на каждое фото, включая пустые кадры:

```json
[
  {"file":"test_001.jpg", "objects":[{"bbox":[10,20,130,180], "type":"manhole", "object_id":"42"}]},
  {"file":"test_002.jpg", "objects":[]}
]
```

```bash
python src/pipeline.py --variant boxes_dino \
  --images data/test_images --boxes data/test_boxes.json --out out/boxes
```

Эта команда использует уже обученный чекпоинт. Чтобы обучить его в том же запуске, добавьте `--train always --annotations data/train_boxes.json --train-images data/train_images`. Тип в тестовой рамке должен совпадать с типом обучения; его можно опустить.

Для обоих маршрутов в `--out` сохраняются `objects.csv`, `repair.csv`, `review.csv`, `preds.json` и `annotated/`. `review` означает неопределённость, а не исправность. Объект, который детектор не нашёл, в эти списки не попадёт.

### Оценка на разметке

Добавьте независимый набор в `config.toml`:

```toml
[datasets.final_dev]
labels = "data/dev_boxes.json"
images = "data/dev_images"
```

JSON оценки содержит истинные рамки, типы и состояния. Затем:

```bash
python src/pipeline.py --variant det_dino --dataset final_dev
```

Метрики и ошибки — в `runs/final_dev__det_dino/`. `--dataset` не поддерживает `boxes_dino` и `photo_dino`; для готовых рамок нужна отдельная оценка по истинным состояниям. Для сравнения найденных и эталонных рамок при наличии сохранённого прогона:

```bash
python src/poc/compare_crops.py final_dev runs/final_dev__det_dino/preds.json
```

При оценке одинаковой разметки с разными `split` скрипт проверяет, что они различаются. Для разных файлов он не может проверить отсутствие пересечений: группируйте по объекту, месту и серии кадров самостоятельно.

## 5. Qwen без обучения

```bash
python src/pipeline.py --variant qwen235 \
  --images data/test_images --limit 5 --out out/qwen_smoke
python src/pipeline.py --variant qwen235 \
  --images data/test_images --out out/qwen
```

Для поиска объектов через Mask2Former используйте `--variant det_qwen235`. Эти варианты не обучаются на train. Перед запуском проверьте `[taxonomy]` и `[names]` в `config.toml`, а также возможность и разрешение использовать API. Для размеченного набора вместо `--images` можно указать `--dataset final_dev`.

Mask2Former ищет только категории, предусмотренные моделью и `[detector].classes`; настройка словаря не обучает её новым типам. В частности, оборудование на опоре в стандартной конфигурации не выделяется как отдельный класс.

## 6. Параметры и диагностика

| Параметр | Назначение |
|---|---|
| `--train never` | Использовать готовый чекпоинт; значение по умолчанию |
| `--train if-missing` | Обучить, только если файл модели отсутствует; не проверяет актуальность данных |
| `--train always` | Обучить заново; существующий чекпоинт будет перезаписан |
| `--checkpoint ПУТЬ` | Чекпоинт для обучения или предсказания; для обучения `photo_dino` имя должно быть `photo_dino.joblib` |
| `--images` / `--dataset` | Фото для предсказания / имя размеченного набора для оценки; указывайте что-то одно |
| `--out` | Папка результатов предсказания и `final`; `--dataset` сохраняет результаты в `runs/` |
| `--training head\|tail\|auto` | Режим обучения целых фото, не кропов |
| `--dry-run` | Проверить входные параметры без работы моделей |

При ошибке отсутствующего чекпоинта задайте обучение и необходимые данные или укажите существующий `--checkpoint`. При ошибке загрузки весов проверьте локальные папки, конфиг и окружение. При `401` Label Studio проверьте тип токена и доступ; при `401/429` Qwen — ключ и лимиты. Не отправляйте токены в чат и не коммитьте `.env`.

Если нужно только показать работу системы в интерфейсе:

```bash
streamlit run src/app.py
```

Интерфейс использует уже подготовленные модели и настройки, сам классификатор не обучает. Проверяйте метрики на независимых данных, вручную просматривайте `review` и кадры без обнаруженных объектов.

## 7. Другая ветка

Эта инструкция относится к текущим `main`/`econom_eval` с добавленным `src/pipeline.py`. В `origin/matthew-branch` есть отдельная реализация каскада, аугментации и другие бэкенды детектора; единый скрипт из этой рабочей копии там может отсутствовать. Не переносите команды и настройки между ветками без проверки. Не переключайте ветку с несохранёнными изменениями.
