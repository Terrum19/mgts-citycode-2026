# Финальный план

## Идея

До финала собираем **свой валидационный датасет** и **один стенд оценки**, на котором честно
сравниваем три подхода. На финале подставляем их классы, перепроверяем на их данных и
показываем победителя. Систему держим простой: никаких ансамблей из пяти моделей.

## Что должен выдавать прототип (по условиям кейса)

На каждое фото: рамка + тип объекта + статус + вид повреждения из их списка + 1–2 предложения описания.
Итог: картинки с рамками + таблица «на проверку/ремонт» с координатами/ID + выгрузка (CSV).

## Три варианта

Во всех вариантах **одинаковые** промпт, JSON-схема ответа и список классов (из конфига).

| # | Схема | Модель |
|---|---|---|
| 1 | Детектор (Mask2Former-Vistas panoptic) → вырез объекта → VLM по вырезу | лучшая VLM из вариантов 2–3 |
| 2a | Только VLM: рамки + статус одним запросом | Qwen3-VL-8B локально (M4, MLX) |
| 2b | Только VLM | `qwen/qwen3-vl-235b-a22b-instruct` (OpenRouter, платно, центы) |
| 3 | Только VLM | бесплатные OpenRouter: `google/gemma-4-31b-it:free`, `nvidia/nemotron-3.5-super-vl:free` |

Формат ответа модели:
```json
{"objects": [{"type": "manhole|pole|cabinet", "bbox": [x1, y1, x2, y2],
              "status": "ok|bad", "damage": "<класс из списка или null>",
              "description": "..."}]}
```

## Валидационный датасет

**Состав (~100–150 фото):**
- ~70–100 кадров из **Яндекс Панорам**: точки объектов из OpenStreetMap
  (`man_made=manhole` + `manhole=telecom`, `highway=street_lamp`, `power=pole`,
  `man_made=street_cabinet`) → ближайшая панорама → камера наводится на объект →
  скриншот через Яндекс Карты JS API (`ymaps.panorama.locate` + `Player`) в Playwright.
  Реальный ракурс «с машины», проверяем поиск объектов.
- ~50 фото **с повреждениями** из поиска картинок («открытый люк», «разбитый люк»,
  «провалившийся люк», «наклонённая опора», «оборванный кабель на столбе»).
  На панорамах почти всё целое — без этих фото статус не проверить.

**Разметка — только руками** (модели как источник истины не используем), в Label Studio:
рамка + тип + статус + вид повреждения. 150 фото на 5 человек ≈ 1 час.

**Временный список повреждений** (на финале заменим их списком):
- колодец: нет крышки / открыта или сдвинута / сломана / просела или выступает;
- опора: наклон / коррозия или разрушение / провисшие или оборванные кабели.

## Метрики (один скрипт для всех вариантов)

| Что | Метрика | Зачем |
|---|---|---|
| Поиск объектов | Полнота и точность при IoU ≥ 0.5, по типам | Нашёл ли объект, не выдумал ли лишних |
| Статус | **Полнота по «bad»** + F1 | Пропустить сломанный объект хуже, чем лишний раз проверить |
| Вид повреждения | Точность на верно найденных повреждённых объектах | Правильно ли назван тип поломки |
| Практичность | сек/фото, $ на датасет, доля битых JSON | Выживет ли на финале |

Плюс 20 описаний смотрим глазами.

## Код

```
src/
  collect/      скрейпер: OSM → панорамы; поиск картинок с повреждениями
  variants/     predict(image) -> list[obj] — по одной функции на вариант
  evaluate.py   predictions + разметка -> таблица метрик
  app.py        Streamlit: загрузка → рамки → таблица на ремонт → CSV
config.yaml     типы объектов, список повреждений, промпт, модель, base_url
```

OpenRouter, `mlx-vlm` и llama.cpp говорят на OpenAI-совместимом API → облако и локальная
модель переключаются сменой `base_url` + имени модели в конфиге.

## Финал: 3 часа

| Время | Что |
|---|---|
| 0:00–0:20 | Разбираем данные и таблицу, вписываем их классы повреждений в конфиг |
| 0:20–0:50 | Размечаем 30–50 их фото для проверки; параллельно прогон основного варианта |
| 0:50–1:50 | Пересчитываем метрики на их данных, доводим промпт, при необходимости переключаем вариант |
| 1:50–2:20 | Прогон тестовых фото, перечень на ремонт, карта |
| 2:20–3:00 | Презентация (таблица сравнения подходов — в слайды). Новых фич не добавляем |

Если на их фото по одному объекту крупным планом — детектор не нужен, остаётся вариант 2/3.

## Запасные идеи (только если основное не тянет)
- Рамки от Mask2Former неточные на мелких объектах → Grounding DINO (`IDEA-Research/grounding-dino-base`).
- Статус нестабилен → классификатор на эмбеддингах DINOv2 по вырезам (обучается за секунды на 30–100 примерах).
- Нужен быстрый детектор под Москву → дообучить YOLO на псевдоразметке панорам.
