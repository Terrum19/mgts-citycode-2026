# Сбор панорам: инструкция для команды

Скрипт снимает кадры из Яндекс Панорам в точках, где по OpenStreetMap стоят колодцы, шкафы
и фонарные опоры. Каждый снимает **свою часть точек** (шард), уже снятое командой пропускается.
Один запуск — до 90 точек, это укладывается в бесплатный суточный лимит ключа (100 запросов).

## Один раз: подготовка (≈ 20 минут, из них 15 — ожидание активации ключа)

1. **Node.js ≥ 22** (`node --version`) и **Google Chrome** (или Chromium).
2. Склонировать репозиторий и обновить: `git pull`.
3. **Свой ключ Яндекс Карт** на [developer.tech.yandex.ru](https://developer.tech.yandex.ru):
   - «Подключить API» → **JavaScript API и HTTP Геокодер** → получить ключ;
   - в настройках ключа → **Ограничение по HTTP Referer**: две строки `citycode.test` и `localhost`;
   - **Ограничение по IP — оставить пустым**, секреты и подпись запросов — не включать;
   - подождать **15 минут**: раньше ключ не активируется.
4. В корне проекта создать файл `.env` (он в `.gitignore`, в git не попадёт):
   ```
   YANDEX_MAPS_API_KEY_PANORAMS=твой-ключ
   ```
5. **Российский IP для Яндекса.** С зарубежного IP (VPN) ключ не принимается и отвечает
   `Invalid API key`. Либо выключи VPN на время съёмки, либо добавь в VPN-клиенте правило
   «напрямую» для доменов `yandex.ru`, `yandex.net`, `yastatic.net`.

## Каждый день: съёмка

```bash
git pull                                              # свежий список уже снятых точек
node src/collect/pano/capture.mjs --shard 2/4         # свой номер из таблицы ниже
node src/collect/pano/pack.mjs --name petya           # упаковать результат
```
Получится `panoramas_petya_<дата>.tar.gz` — отправь его Саше (Telegram или диск).

| Кто | Шард |
|---|---|
| Саша | `1/4` |
| thebulkapro | `2/4` |
| Дмитрий | `3/4` |
| [4-й участник] | `4/4` |

Шардов 4: если кто-то уже запускал с `/3`, просто переходи на свой `/4`. Уже присланное
и слитое через `merge.py` не переснимется; возможны единичные дубли из ещё не присланных архивов — `merge.py` их отбросит.

Скрипт можно запускать повторно: уже обработанные точки он пропускает, а при ошибке API
сразу останавливается, чтобы не тратить лимит.

## Если что-то пошло не так

| Сообщение | Что делать |
|---|---|
| `YANDEX_MAPS_API_KEY_PANORAMS не найден в .env` | Проверь шаг 4: файл `.env` в корне проекта, имя переменной точно такое |
| `Invalid API key` / `locate_error scriptError` / `ERR_BLOCKED_BY_ORB` | Яндекс не принял ключ. По порядку: 1) в Referer есть **`citycode.test`** (одного `localhost` мало); 2) ограничение по IP пустое; 3) прошло 15 мин после создания **и после каждой правки** ключа; 4) VPN выключен или Яндекс идёт напрямую; 5) ключ в `.env` без пробелов и кавычек. Проверка: открой в браузере `https://api-maps.yandex.ru/2.1/?lang=ru_RU&apikey=ТВОЙ_КЛЮЧ` и найди `apikeyValid`: `false` — пункты 2–5; `true`, а скрипт падает — пункт 1 или VPN включён для терминала, но не для браузера |
| `Не нашёл Chrome/Chromium` | Укажи путь: `--chrome "/путь/к/chrome"` |
| `no_pano` / `too_far` у части точек | Нормально: рядом с объектом нет панорамы, точка помечается и больше не запрашивается |

## Для координатора

```bash
python3 src/collect/pano/merge.py panoramas_*.tar.gz   # слить архивы, обновить configs/panoramas_done.txt
git add configs/panoramas_done.txt && git commit -m "Panoramas done list" && git push
```
Список целей пересобирается так (обычно не нужно):
`python3 src/collect/osm_points.py --all --out data/raw/osm_all.json && python3 src/collect/pano/make_targets.py`.

Кадры — © Яндекс, используются только как проверочный набор внутри команды и в git не коммитятся.
